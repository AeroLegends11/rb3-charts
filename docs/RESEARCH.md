# Architecture and research notes

Research date: 2026-09-10. Objective: locally generated, synchronized RB3 charts
with a usable automatic workflow. Musical precision has priority over coverage.

## Toolchain choices

- [Onyx toolkit source](https://github.com/mtolly/onyx) and
  [manual](https://onyxite.org/toolkit/readme.html): use its Windows CLI to import
  song.ini/MIDI/audio, add an RB3 target, and build a CON. Its bundled Magma
  compiler handles validation and autogenerated animation/venue content.
  Tested release: **20251011**. CLI schema was checked in `Onyx/CommandLine.hs`
  and `Onyx/Project.hs`; defaults retain required Magma validation.
- [Five-fret encoding](https://github.com/mtolly/onyx/blob/master/haskell/packages/onyx-lib/src/Onyx/MIDI/Track/FiveFret.hs):
  Easy/Medium/Hard/Expert bases 60/72/84/96, lanes +0..4, forced HOPO +5,
  forced strum +6, overdrive 116, solo 103. Initial exporter leaves natural HOPO
  interpretation to the game rather than forcing speculative markers.
- [Drum encoding](https://github.com/mtolly/onyx/blob/master/haskell/packages/onyx-lib/src/Onyx/MIDI/Track/Drums.hs):
  same difficulty bases, kick +0, red +1, yellow +2, blue +3, green +4;
  tom markers 110/111/112, overdrive 116, activation lanes 120..124.
- [Demucs upstream](https://github.com/facebookresearch/demucs): six-source
  model supplies guitar and piano; fine-tuned four-source models supplement
  drums and bass in precision mode. The original project notes piano artifacts
  and limited maintenance; no claim of perfect stems. Version 4.0.1 is pinned.
- [Basic Pitch](https://github.com/spotify/basic-pitch): version 0.4.0 ONNX model
  for guitar/bass/keys, applied to separate instruments. Chord heuristics remain
  distinct from transcription. ONNX avoids TensorFlow's incompatible legacy
  dependency on this Python 3.12 environment.
- [ADTOF](https://github.com/MZehren/ADTOF) links to
  [ADTOF-pytorch](https://github.com/xavriley/ADTOF-pytorch), a trained drum model
  with bundled weights and a small runtime dependency set. We pin commit
  `85c192e78f716ea0b111cc8a5ee4a8f6a3a4f8a9`, load weights strictly, and retain
  class activation diagnostics. This replaces a spectral-only baseline.
- [librosa dynamic tempo tutorial](https://librosa.org/doc/0.11.0/auto_examples/plot_dynamic_beat.html)
  and [beat_track API](https://librosa.org/doc/0.10.2/generated/librosa.beat.beat_track.html):
  time-varying BPM estimates can drive beat tracking. Output intervals form the
  shared seconds-to-beats map; onset timestamps are not aggressively quantized.

## Data flow

Audio → decode stereo 44.1k → cached separation → tempo map + per-instrument
transcription → deterministic Expert chart → nested reductions → MIDI/audio
with identical lead-in → validation → local listening preview → Onyx/Magma CON.

Long drum inference uses 30-second windows with two seconds of context on each
side. Only each window's central predictions are kept. Windows share the original
audio feature timeline; padding does not change onset timestamps.

## Precision and honest confidence

Tests cover MIDI timing across drifting tempos, pickups, repeat-pattern mapping,
reduction ancestry, lane constraints and malformed charts. These are engineering
checks; they do not measure human chart quality. Tempo consistency and model
activation strength are heuristic confidence signals, not calibrated correctness
probabilities. Generated audio provides known event timing, but a real mixed
recording and console playtest are still required.

## Learned structure model datasets

The rights-traceable prototype uses GuitarSet for real guitar attacks/chords,
Slakh2100-redux for aligned multitrack examples, and Guitar-TECHS for isolated
electric-guitar examples. All three are published under CC BY 4.0. EGSet12 is a
separate CC BY 4.0 held-out electric-guitar check and also publishes an augmented
TabCNN checkpoint. RWC Music Database 2.0 is CC BY-NC 4.0 and must remain isolated
in a noncommercial research experiment rather than being mixed into a permissive
checkpoint.

No verified public dataset teaches Rock Band-specific lane choices, HOPO flags,
difficulty reductions, overdrive, fills, or venue events. The learned component
therefore targets lane-independent attacks, polyphony, sustains, and sections;
deterministic authoring remains responsible for controller gameplay. Official
Rock Band charts remain local post-generation evaluation evidence, not training
labels or runtime inputs.

Every training corpus requires a validated item-level manifest containing source
and version, separate audio/annotation licenses, attribution, commercial-use
status, relative file paths and hashes. Splits are artist-disjoint to expose
memorization rather than reporting it as generalization. Feature-index schema 2
cryptographically links each derived artifact to one manifest item and verifies
audio, annotation lineage, split, and license provenance before training.

GuitarSet evaluation additionally keeps both performer identities and musical
progressions disjoint. Feature extraction uses a fixed full-scale dB reference,
not per-file peak normalization, so offline training and later streamed inference
can reproduce the same scale. Validation selects an attack threshold; final test
metrics reuse that threshold without calibration.

The first acoustic checkpoint must not be applied directly to commercial full
mixes. A held-out local probe showed severe under-detection and zero predicted
chords on most songs. Full-mix inference is therefore rejected; electric/full-band
evaluation must use an aligned separated guitar stem or a model trained for the
mixture domain. Local commercial recordings are evaluation evidence only.

The electric-guitar prototype adds positive spectral-change bins to fixed-reference
log-mel features. Cleared validation thresholds still transferred poorly to local
commercial guitar stems, but ranking attack candidates at the existing generated
chart's density improved aggregate official-reference attack F1 on six of seven
available Band-song evaluations. This aggregate comparison does not expose
reference sequences to generation and does not establish chord, lane or gameplay
quality. Learned structure remains offline until calibration and authoring
integration can be validated without tuning on commercial references.

A Guitar-TECHS pilot added twelve amplifier-microphone excerpts from performer P3
to training only; the shared performer split key prevents these excerpts from
being divided across splits. With the prior validation and test sets unchanged,
untouched test attack F1 improved from 0.7311 to 0.7982 and polyphony accuracy
from 0.6009 to 0.8194. On held-out EGSet12, attack F1 remained approximately
unchanged at 0.7994 while polyphony improved from 0.4132 to 0.6737. However, its
validation-selected attack threshold severely under-detected the 13 held-out
commercial stems, so it is not approved for generation.

The published EGSet12 TabCNN checkpoint is exposed through an optional offline
provider that records checkpoint, audio and attack-input hashes plus source,
license and attribution. On EGSet12, sampling it at structure-model attacks
measured 0.7184 polyphony accuracy, 0.5987 exact pitch-set agreement and 0.8855
agreement on at least one pitch. A full replacement experiment reduced
official-reference chord-class agreement, so this evidence is not applied to
chart generation. AMT-Tools remains an explicitly optional research dependency,
not part of the standard installation.

All figures in this section are automated metrics or post-generation evaluation.
Neither the Guitar-TECHS checkpoint nor TabCNN integration has been listening
reviewed or Xbox-playtested.

REAPER remains useful for manual chart corrections, but is not required for this
automated build path. We do not invent a new package format or implement an
alternative Magma validator. See README for omitted features and limitations.
